# Independent read-only diagnostic service
This component provides Hostinger diagnostics through the existing owner-authorized MCP connection using the distinct device_id ANTHARES-HOSTINGER. Supported operations are system_info, session_status and capabilities. Default Windows dispatch is untouched. Every other operation on this device is rejected before network access.

The Hostinger endpoint verifies the existing gateway Ed25519 signature, method, exact path, timestamp and signer. GET replay within the short freshness window has no effect beyond the same read; this endpoint never creates a job or writes a result to a second ledger. Request-budget metadata is private, contains no tokens and bounds process creation. Missing/malformed auth is rejected before creating any child. The PHP wrapper runs only its fixed Node diagnostic handler, with JSON stdin, output limits, deadline and child cleanup. Client input never chooses a program, argument, file or shell command.

Private deployment config lives outside public_html under the site's anthares-secure/independent-service directory. It contains the pinned PUBLIC signing key, existing Node and Kilo executable paths, existing private gateway socket path and executor_id. No private signing key, device token, model key or OAuth credential is copied. The public PHP endpoint is the only public file. The handler and config remain private.

Host observations describe the shared host; they do not certify the account resource allowance. Gateway health is not inference readiness. Generic shell, agents, media processing, publishing, mutating jobs and migration acceptance are unsupported. Windows repair and the refused selector proposal remain excluded. This component does not reproduce those actions or provide another route for them.

Tests use synthetic keys and isolated temporary files in CI. They include real PHP-to-Node execution, Ed25519 verification and OAuth MCP dispatch. Production acceptance requires real signed calls through both connectors and anonymous denial. There is no installer or administrative restart command in this change. Keep all existing providers and queues; no new persistent worker, paid resource or background job is needed.
